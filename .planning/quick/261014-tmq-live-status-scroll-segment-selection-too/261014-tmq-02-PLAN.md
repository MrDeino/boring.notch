<objective>
Text selection in the chat like the CLI: drag to highlight in transcript rows, auto-copied to the clipboard on mouse-up with a brief 'Copied' toast. Selecting never triggers tap-to-expand; a plain click still does. Own commit(s), after plan 01.

Mechanism (decided): an NSTextView-backed selectable text, not SwiftUI `.textSelection(.enabled)`. Reasons: `.textSelection` has no selection/mouse-up callback (no auto-copy), its behaviour in this non-activating, normally non-key panel is unverified, and it gives no way to tell a plain click (must expand) from a drag (must not). An NSTextView subclass gives both: its `mouseDown` runs AppKit's own tracking loop until mouse-up, so after `super.mouseDown` returns the selection is final; length 0 = plain click -> call the expand action explicitly; length > 0 = copy. This also avoids the ed9680a/notes failure mode (AppKit text view swallowing clicks) because the swallowed plain click is forwarded on purpose.

Selection is per row (each row's text is its own text view); dragging across rows is not supported. Starting a selection in one row clears the previous row's selection.

Output: OrchestratorSelectableText + wiring in ChatBlockRow + 'Copied' toast + hit-test checks.
</objective>
