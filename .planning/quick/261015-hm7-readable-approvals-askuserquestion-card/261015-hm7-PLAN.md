<design_findings>
Settled from the code. The executor does not need to re-derive any of this.

- **The Phase 6 card already covers AskUserQuestion completely.** See `detectPromptCard` in OrchestratorPromptParse.swift and `QuestionCard` in OrchestratorPromptCard.swift. It handles header chips (`tabs`/`header`/`progress`), the wrapped question text (reflowed with spaces, in a ScrollView), options with descriptions (`detail`), multiSelect checkboxes (`toggle` → key n, `next` → Tab), multi-question tabs (`goTab` → Tab/BTab), the "Type something" free-text field (`submitFreeText`), Chat about this, and esc. It answers through `PromptCardController.choose/next/goTab/submitFreeText` → `OrchestratorManager.pressKeys` → POST /api/chat `{key}`, with optimistic dismiss. Real captures exist: `Tests/fixtures/question.txt` (1 question, single select) and `Tests/fixtures/multiselect-1.txt` (2 questions, Fruit multiSelect + Color). The card already appears as scene 17, so **no new question view**.
- **Allow/Deny is wrong for questions.** Allow sends "1" or opens the card, and the ⌥⏎ hotkeys would pick option 1. So the question approval must never reach the drop-down or the hotkeys.
- **Every UI consumer reads `OrchestratorApprovalCenter.shared.approval`**, never the manager directly: ContentView lines 59/212/297/541, OrchestratorCompact.swift:20, ClosedReplica. Filtering in the center's sink therefore removes the drop-down, the approval corner radius, the hover-open block and the hotkeys in one place. `OrchestratorManager.approval` stays as it is (its answerApproval is only called from the center).
- **Surfacing the card:** the card lives in the open notch's Orchestrator tab (OrchestratorExpanded.swift:225). The existing `cardRequest` path (ContentView.swift:213) already opens the notch on that tab, so reuse it. When the notch is open, the open notch replaces the closed music live activity, which covers the "over playing music" case. The question card then raises itself to `.expanded` (`PromptCardController.sync`), and that holds a keep-open interaction.
- **What serve sends** (orch.js `approvals.hook`, read-only, other repo): only `tool`, `command` (= `command` || `file_path` || `pattern` || `url` || `JSON.stringify(tool_input)`, whitespace-collapsed, cut at 300 chars) and `description`. `old_string`/`new_string`/`content` are not sent, so **an Edit/Write diff or size cannot be shown from the notch**. Showing it needs a serve change in the orchestrator repo, which is out of scope for this repo (HTTP API only, never touch other projects). The plan shows verb + path and records the gap in the SUMMARY. AskUserQuestion's `command` is truncated JSON, so the screen parse, which is lossless apart from reflowing wrapped lines, is the source of the question text.
</design_findings>
