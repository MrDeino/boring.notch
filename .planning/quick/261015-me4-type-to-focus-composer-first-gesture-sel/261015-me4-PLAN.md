# Type-to-focus composer, first-gesture selection, send retry

## Tasks
1. **Send retry** (`OrchestratorModels.swift`): every POST (text, keys, start/stop, notes, image) goes through
   `orchestratorPostData`, which retries once on a fresh `URLSession` (no pooled keep-alive) when the error is
   `networkConnectionLost`, `cannotConnectToHost` or `notConnectedToInternet`. No retry once any HTTP response came
   back (409, 4xx, 5xx) and none on timeouts (serve may have acted).
2. **First-gesture selection** (`OrchestratorChat.swift`, new `OrchestratorComposerInput.swift`): the composer
   TextField is always mounted instead of being swapped for a `Text` + tap overlay while idle. A click focuses it in
   place (works in the non-key panel), so drag / double-click select at once; focus then opens the typing session
   (`startTyping`: key gate, activation) without touching the selection.
3. **Type-to-focus**: a local keyDown monitor on the chat view (composer shown) passes the event to pure
   `typeToFocusText`. A printable key with no ⌘/⌃, while the notch is open/expanded on the Orchestrator tab, the app is
   active, the panel is key, the composer/terminal/another editable field isn't focused and no question card is
   showing, is appended to the draft, typing starts, and the caret lands at the end. Everything else passes untouched.
4. Tests: `Tests/QuickMe4Tests.swift` (+ `Tests/retry-mock.py`), Debug + Release builds in `./build`.

Untouched: OrchestratorExpand.swift, OrchestratorExpanded.swift, ContentView.swift, Snapshots/ (another run).
